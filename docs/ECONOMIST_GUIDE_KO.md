# 경제학자를 위한 LLM 위키 구축·새 논문 관리 안내

[English](ECONOMIST_GUIDE.md) · [표준 AI 요청문](../START_HERE_KO.md) · [첫 화면](../README.md)

준비된 대시보드의 일상 사용에는 코딩이 필요하지 않습니다. 최초 설치에는 파일과 명령 실행 도구를 갖춘 허가된 AI 에이전트 또는 기술 담당자가 필요합니다. 채팅 답변만으로 설치가 끝나지는 않습니다. 새 위키는 빈 상태에서 시작합니다. 이 문서는 한국어 설명서이며 프로그램 화면 전체의 한국어화를 뜻하지 않습니다.

## 1. 좁은 연구 질문으로 시작하세요

예: 최저임금과 고용, 통화정책 전달, 교육 수익률, 관세 변화. 대상·기간·인구·산업·출처 유형·제외 기준을 정합니다. 연구 전용 보관함을 쓰며 비공개 기업·가계 미시자료를 기본 수집 범위에 넣지 않습니다.

[표준 요청문](../START_HERE_KO.md)을 복사해 질문·새 보관함·선택 자료를 채우세요. 담당자는 읽기 전용 doctor부터 실행해야 합니다. 기본은 Node.js 22+이며 전체 테스트에는 실제 작동하는 Python 3.10+도 필요합니다. Poppler·QMD·Hermes/외부 AI는 별도 허가가 필요한 선택 기능입니다.

## 2. PDF 모음이 아니라 지식을 만드세요

먼저 처리 권한이 있는 논문 두 편을 선택합니다. 에이전트가 식별자·버전을 확인하고 Sources/출처와 Literature/논문 초안을 만듭니다. 모든 Source에 질문, 메커니즘·이론, 데이터·표본·기간, 실제 식별 전략(없거나 해당 없음 명시), 추정 대상, 결과·단위·불확실성, 한계·관련성을 설명하는 요약과 실제 읽은 범위·정확한 인용문·위치가 필요합니다. Literature에는 명세·추론 등 상세 추출을 담습니다. 이론에는 가정·명제가 중요하며 회귀 서식을 억지로 적용하지 않습니다. 인과 식별이나 JEL 코드를 만들어내지 마세요.

필요한 Dataset/데이터, Policy/정책, Method/방법, Theory/이론 기록을 연결합니다. 연구들이 함께 지지하는 내용과 차이를 정리한 Topic/주제 한 개를 요청하세요. 워킹페이퍼와 출판 논문은 같은 연구일 수 있습니다. 같은 표본을 독립 검증 근거로 중복 계산하면 안 됩니다.

중요한 원문을 읽고 저자 주장, 근거, 본인의 판단을 구분하세요. 수치 추출 승인이 정책 권고 승인은 아닙니다.

그다음 셋째 논문으로 **같은 주제**의 실질적 갱신을 요청하세요: 이전 문장 → 제안 문장 → 정확한 출처 근거 → 이유·적용 범위. 편집 전에 허락하며 기존 연구 노트 수정은 기본적으로 Topic 하나, 목차·활동 기록은 별도입니다. 링크 추가만으로 실질적 갱신이 되지 않습니다. 수정 근거가 없다면 결과를 만들지 말고 유지 이유를 기록합니다. 이전 버전과 검토 결정·영수증은 비공개 비색인 보관소에 보존합니다. 실질적으로 바뀐 현재 내용은 `economist-review-needed`로 되돌리고 이전 승인 필드를 승계하지 않습니다. 새 버전은 범위가 명확한 새 전문가 검토로만 승인할 수 있습니다.

## 3. 대시보드 사용하기

Obsidian에서 준비된 연구 보관함을 엽니다. Mac의 Command+P(다른 환경에서는 보통 Control+P)로 명령 목록을 열어 “economy”가 포함된 대시보드 명령을 선택합니다. 없으면 담당자에게 플러그인 활성화를 확인해 달라고 요청하세요.

`tariff`, `gravity`, `DiD`처럼 짧은 단어를 입력하고 제목·저장된 결과를 읽은 뒤 전체 노트와 출처를 엽니다. 검색 결과가 없다고 연구가 존재하지 않는 것은 아닙니다. Reset search는 검색·비교 선택을 초기화합니다.

논문 카드에서 비교 대상을 선택하고 **Compare selected**로 나란히 읽습니다. 계수 크기만 보지 말고 추정 대상, 국가, 기간, 데이터 버전, 추론 방법을 비교하세요.

**Graphical paper links**는 기록된 연결과 유사성 제안을 보여줍니다. 유사함은 합의·인과관계·독립 재현을 입증하지 않습니다. 자료·방법 기록은 탐색에 도움이 되지만 그 자체로 실증 근거가 되는 것은 아닙니다.

선택형 의미 검색에는 로컬 모델과 색인 설정이 필요합니다. 기본 검색 옆 **Semantic**은 현재 질문으로 로컬 의미 검색만 실행합니다. **Semantic / LLM services**는 실행 없이 설정 화면을 엽니다. 질문 줄에서 검색 방법을 고르고 Run semantic search를 누릅니다. 조작 버튼은 결과 위에 있으며 결과는 활성 메타데이터 필터를 따릅니다. 색인 자체는 허용된 연구 폴더 전체를 대상으로 합니다.

외부 AI 초안은 비교 노트 선택(없으면 로컬 후보 검색) → **Preview synthesis evidence** → 경제학 구조화 요약·정확한 발췌문·질문/경로/제목/본문 전송 JSON 확인 → 전송 동의 → **Generate grounded draft — provider call** 순서입니다. 명시한 제공자·모델·Python 설정이 필요하며 비용·세션 보관이 발생할 수 있습니다. 질문·선택·필터·새로고침·화면 변경 시 동의가 무효화되어 다시 미리봐야 합니다. Cancel은 프로세스 트리를 종료하고 늦은 응답을 무시하지만 이미 전송한 내용을 회수하지는 못합니다. 초안은 자동 저장하지 않으며 Ask this collection은 계속 로컬 발췌만 제공합니다. 별도 허락 없이 비공개 내용을 보내지 마세요. 인용 검증이 인과 식별·해석·계량경제학적 타당성을 보장하지는 않습니다. [설정과 제한](OPTIONAL_SERVICES.md#dashboard-configuration-and-use)을 읽으세요.

## 4. 새 논문은 같은 순서로 처리하세요

> 기존 기록 규칙·목차·최근 활동 기록부터 읽어주세요. 선택한 허가된 논문을 범위 안에서 처리하고 버전·중복을 확인해 원자료를 보존해 주세요. 출처 위치가 있는 결과와 미확인 항목을 추출하고 영향을 받는 기존 주제·데이터·정책·방법을 찾아주세요. 이전 문장, 수정 제안, 출처와 이유를 제시하고 제 이전 결정을 보존해 주세요. 새로운 해석은 검토 대기로 두고 허가된 통합 후 목차·활동 기록, 구조 점검, 검색 색인을 갱신해 주세요.

PDF를 넣기만 해서는 처리가 끝나지 않습니다. 주제 통합이 대기 중이면 그대로 보고해야 합니다. 정당한 이유가 있을 때만 새 주제를 만들고 페이지 수를 늘리려고 중복 개념을 만들지 않습니다.

## 5. 경제학 특유의 주의점

- 인과 결과 표시: 가정하의 주장이지 식별의 자동 인증이 아닙니다.
- 사전 추세·밀도·1단계 검정: 진단이지 가정의 증명이 아닙니다.
- 데이터 개정: 결과에 영향을 줄 수 있습니다. 자동 재실행·덮어쓰기보다 재검토가 먼저입니다.
- 정책 발표: 시행 또는 실제 처치 노출과 다를 수 있습니다.
- 무역 수치: 통화·가격 기준, CIF/FOB, 품목분류 판, 결측·0의 구분을 확인합니다.
- 재현 표시: 실제 실행 기록과 결과 대조가 필요합니다. 합성 자료는 코드 동작만 시험합니다.
- 해시 일치: 파일 내용이 같다는 뜻이지 과학적 최신성을 뜻하지 않습니다.

## 6. 검토와 유지관리

논문 처리 후 Refresh wiki를 누릅니다. 의미 검색의 색인은 별도입니다. 보고서가 설정되어 있다면 Database health에서 최신 구조 점검을 읽습니다. 메타데이터 누락·중복 후보·깨진 링크·들어오는 연결이 없는 노트·변경된 의존 관계는 수정 요청이지 자동 결론이 아닙니다.

담당자에게 출처 연결, 식별자 모호성, 영향받는 해석, 주제 통합 순으로 우선 검토를 요청하세요. 구조 점검이 지식을 다시 쓰지는 않습니다. 매주 중요한 소수의 수정 제안을 검토하고 주기적으로 범위·분류와 비공개 백업 복원을 확인합니다. 정기 실행은 별도 설정이 필요하며 휴대전화 알림을 자동 보장하지 않습니다.

검토자·날짜·확인한 자료·결정·한계를 기록합니다. ‘추출은 승인, 인과 해석은 보류’처럼 구분하세요. 경고를 지우려고 승인하지 마세요.

## 7. 문제 해결과 안전

대시보드 없음: 보관함·플러그인 확인. 검색 없음: 한 단어와 새로고침. 요약 없음: 허가된 원문 추출 요청. 오래된 보고서: 실행 일정·실패 확인. 의미 모델 오류: 기본 검색 사용. 잘못된 결과: 출처 확인·우려 기록·판단 보류.

문의할 때 버튼·검색어·오류를 설명하고 화면에서 비공개 정보를 지우세요. 비밀번호·API 키를 채팅으로 보내지 마세요. GitHub 구축 저장소와 검색 색인은 실제 연구 자료의 백업이 아닙니다.
