# 모은 논문을 저장하고 연결된 위키 초안 만들기

[English](FOLDER_INTAKE.md) · [두 논문 → 주제 → 셋째 논문 갱신](../START_HERE_KO.md)

## 일상 사용 순서

1. 담당자에게 개인 자료·비공개 자료와 분리된 **새 논문 수신 폴더**를 지정해 달라고 요청합니다. 원문 저장 폴더와도 구분합니다.
2. 처리 권한이 있는 논문을 넣고 다운로드가 끝난 뒤 실행합니다. 텍스트가 포함된 PDF, TXT, Markdown이 초기 대상입니다. 스캔 PDF는 별도 OCR이 필요합니다.
3. “새 논문을 먼저 미리 보여주고, 검증된 원본 사본을 저장한 뒤 출처와 연결된 연구 초안·관련 문서 제안을 만들어 주세요”라고 요청합니다.
4. 원본을 수신 폴더에서 지우는 이동은 별도로 허용해야 합니다. 초기에는 복사 모드를 권합니다.
5. 연구 초안과 관련 문서를 확인합니다. 단어가 비슷하다는 추천은 확인된 연구 관계·독립 검증·인과관계가 아닙니다.
6. 생성된 근거 묶음을 허가된 AI 에이전트에게 주어 주제·개념·방법·이론·데이터·정책 기록을 제안하게 합니다. 기존 기록을 먼저 찾고 실제 인용 문장으로 뒷받침해야 합니다.
7. 제안을 검증한 뒤 검토 대기인 새 문서로 반영합니다. 기존 검토 문서는 덮어쓰지 않으며, 기존 주제 수정은 통합 제안으로 남깁니다.
8. 대시보드를 새로고침하고 필요하면 별도 의미 검색 색인을 갱신합니다. 실패·보류 기록을 확인합니다.

## 복사하여 사용할 요청문

> [수신 폴더]의 선택한 논문을 [보관함]의 기존 범위·기록 규칙에 맞추어 처리해 주세요. 미리보기부터 하고 원본 바이트와 검토된 노트를 보존하세요. 출처와 연결된 연구 초안·관련 문서 후보를 만든 뒤 생성된 근거 묶음으로 실제 인용 문장이 있는 주제·개체 제안을 작성해 주세요. 유사성 추천과 확인된 관계를 구분하고 식별자·수치·인과 검증·사람의 승인을 만들어내지 마세요. 저장·복사·이동·생성된 항목과 남은 통합 작업을 알려주세요. 별도 허락 없이 외부 서비스로 원문을 보내지 마세요.

## 알아둘 한계

자동으로 뽑은 문장은 LLM 종합이 아닙니다. 실제 의미를 정리하고 새 개체를 만드는 단계에는 허가된 에이전트의 제안이 필요합니다. 인용 일치가 해석의 타당성을 보장하지 않습니다. PDF 텍스트 추출은 표·수식·서지정보 검증이나 전체 논문 평가가 아닙니다.

파일의 원본 해시로 중복과 저장 일치를 확인합니다. 이름이 같아도 다른 파일일 수 있습니다. 미리보기는 원본을 이동하지 않습니다. 적용과 삭제를 수반하는 이동은 명시적 선택이며 원본은 저장 검증과 필요한 문서 기록이 끝날 때까지 보존해야 합니다. 실패 시 완료로 표시하면 안 됩니다.

수신 폴더에 들어왔다고 연구 범위나 과학적 타당성이 승인되는 것은 아닙니다. 비공개 기업·가계·행정 미시자료 또는 개인 폴더 전체를 지정하지 마세요. 실제 연구 자료·처리 기록·모델은 GitHub 구축 저장소에 올리지 않습니다. 별도 백업도 필요합니다.

## 기술 담당자에게

구현된 옵션과 제안 형식은 `node scripts/intake-papers.cjs --help`로 확인합니다. 경제학에서는 `--content-evidence`가 필요하지 않습니다. 의료 분야의 수집 관문을 복사하지 마세요. [실행 규칙](AGENT_RUN_CONTRACT.md)의 질문·메커니즘·자료·식별·추정 대상·결과·한계·위치가 있는 출처 요약은 별도 완성 작업입니다. 저장·인용 일치는 이를 대신하지 않습니다. 추가형 제안은 기존 주제를 수정하지 못합니다. 셋째 논문의 같은 주제 갱신은 이전/제안 문장과 근거를 보여주고 허락받아 따로 수행합니다. 이전 버전·결정을 보존하고 바뀐 현재 내용은 `economist-review-needed`로 되돌립니다. 작은 격리 시험부터 하고 상태 기록은 보관함 밖에 둡니다. PDF 추출에는 별도 설치한 `pdftotext`가 필요합니다. 이 기능은 요청 시 실행하며 상시 감시·정기 실행·자동 OCR·화면 버튼·외부 모델 설치를 자동으로 켜지는 않습니다.
