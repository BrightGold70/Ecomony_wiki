# Economics onboarding acceptance checklist

This checklist is for a new installation, not evidence that every service is already configured.

Core acceptance (no paid provider or model required):
- Run read-only doctor and identify actual Node version; install/open Obsidian manually.
- Initialize only an authorized new vault; no private microdata or personal paper library copied to Git.
- Run labelled synthetic first-wiki-demo at a new output path. Inspect real raw-byte hashes, retained inbox, Source and Literature records, quote-grounded topic proposal, index/log, lint/search/graph receipts.
- Demonstrate first two papers → topic → third substantive proposed update. Preserve earlier version/decision separately; current material edits remain economist-review-needed pending new scoped review.
- Choose the clinician-equivalent economist's own field (labor, macro, development, finance, public, industrial organization, econometrics, trade, or other declared scope); no universal trade inclusion rule.
- With real papers separately authorized, verify working-paper/published version, common datasets/samples, estimand, assumptions, inference and evidence actually read. Descriptive evidence is not causal proof; theory/diagnostic/replication claims need their own provenance.

Optional service acceptance is separate:
- Python3.10+ enables full tests and synthesis; PYTHON selects explicit interpreter.
- PDF text extraction requires pdftotext; OCR separate.
- QMD isolated runtime/models/collection receipt must pass an actual vector-contribution query, not merely install.
- Official Obsidian CLI enabled and exact vault binding verified; shipped CLI bridge can await async eval and flush large pipe output.
- Hermes synthesis needs authenticated named provider/model and explicit preview permission. Test synthetic content first; no credentials in data.json.
- Publication checking coverage and scheduling must be explicitly configured; no-notice-found is not validity. Search indexes are not backups.

Record actual commands, results, failures and unconfigured services. Do not claim installed desktop or cross-platform support from automated synthetic tests alone. The assistant must never invent empirical results, record a real economist's approval, or erase old reviewed interpretations.
