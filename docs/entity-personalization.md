# Personal research entity navigation

The economics dashboard starts with **no personal entity buttons**. There is no universal topic list or clinical scope. Use **Edit my entities** to choose your own navigation.

- Each row chooses **Metadata field** (`country`, `product`, `method` or `evidence_kind`), **Exact metadata value**, and a separate **Display name**. The three aligned column headers appear once above the rows. **Add entity** starts a blank row with `country` as the field; it does not select a country or add a navigation button until saved.
- Type a recorded scalar metadata value, or explicitly **Pick metadata suggestion**. Suggestions are discovered from indexed metadata; they never add buttons automatically, even on Refresh wiki. Matching uses the indexed scalar value, case-sensitively—not title, label, synonyms, list membership or inferred topics.
- Use up/down to order buttons, edit the display name to rename one, and **Remove** to hide one. **Save my entities** persists the selection; **Cancel entity edits** discards the draft. Saving no rows stays empty after reopening. A failed save leaves the draft editable and original buttons unchanged.
- Clicking a personal button opens a reference pane across all nine indexed compiled categories, independent of current keyword/metadata filters or comparison selections. The pane shows both your label and the exact field/value, matching notes, and separately verified wiki/source/stored-original actions when available. Unknown values give zero matches. Existing filters remain unchanged.
- Preferences are local installation plugin data: `researchEntities: [{"field":"country","value":"Korea","label":"My Korea research"}]`. This is an illustrative opt-in row, **not a default**. Saving reloads the latest plugin data and replaces only `researchEntities`, preserving repository, provider/model, `economyQmdRoot` and unrelated settings. It is not per-user authentication on a shared installation.
- At most 50 rows; field/value pairs and display names must each be unique. Values and labels must be nonblank strings of 1–100 characters, with no surrounding whitespace or control characters. Invalid saved preferences show no buttons and never restrict search. User text is rendered as text, not HTML.

Personalization writes no notes, rewrites no source metadata and does not change collection policy, automatic evidence eligibility or economist review. It does not transmit evidence or invoke a provider. Semantic search remains beside the main keyword field; the Semantic / LLM services question/method row and permission-gated controls remain above evidence previews. Filesystem scope and symlink protections remain in force.

Verification uses synthetic VM DOM events and offline service/navigation tests; it does not establish live Obsidian visual acceptance or deploy a real economics vault.
